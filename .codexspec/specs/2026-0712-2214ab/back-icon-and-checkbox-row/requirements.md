# 返回按钮图标化与单词卡片复选框同行

## 需求背景

功能实现已符合预期，但用户反馈两个 UI 细节不美观：

1. 设置界面与查词历史界面左上角的“← 返回”按钮视觉粗糙，与整体风格不匹配。
2. 查词历史卡片中，复选框单独占一行，显得拥挤且割裂；用户希望复选框与单词保持在同一行。

## 已确认需求 (NEED)

| ID | 条目 | 状态 |
|---|------|------|
| **NEED-001** | 将设置页与查词历史页左上角的返回按钮从“← 返回”文字按钮，改为使用用户提供的 SVG 图标 + “返回”文字 | confirmed |
| **NEED-002** | 将查词历史单词卡片的复选框从当前单独一行，移动到单词所在行，位于单词文本之前并保持同一行对齐 | confirmed |

## 约束条件 (CON)

| ID | 条目 | 状态 |
|---|------|------|
| **CON-001** | 仅做 UI 调整，不改动返回按钮的点击行为、复选框的选中逻辑或批量删除业务逻辑 | confirmed |
| **CON-002** | 复选框仍应阻止点击事件冒泡到卡片，避免误触进入详情 | confirmed |
| **CON-003** | SVG 图标颜色在暗色模式下应可见；使用 `fill: currentColor` 自动适配按钮文字色 | confirmed |
| **CON-004** | 所有既有测试必须继续通过；新增样式调整应在现有测试断言范围内兼容 | confirmed |

## 已确认决策 (DEC)

| ID | 条目 | 用户证据 |
|---|------|---------|
| **DEC-001** | 返回按钮 SVG 使用用户提供的 `<svg>` 路径，保留为内联 JSX，不新增外部图标依赖 | 用户消息附带 SVG |
| **DEC-002** | 复选框移至单词左侧并保持同一行 | 截图显示复选框在单词前面 |
| **DEC-003** | 返回按钮保留“返回”文字，仅将“←”替换为 SVG 图标 | 用户选择“图标+文字” |
| **DEC-004** | SVG 在暗色模式下使用 `currentColor` 自动适配 | 用户选择“自动适配” |

## 排除范围 (OUT)

| ID | 条目 | 状态 |
|---|------|------|
| **OUT-001** | 不修改返回按钮的布局尺寸、位置与响应行为 | confirmed |
| **OUT-002** | 不新增或删除任何业务逻辑、状态管理或数据持久化 | confirmed |
| **OUT-003** | 不引入新的图标库或字体库 | confirmed |

## 确认日志

- 2026-07-12 22:15: 用户通过图片与消息提供 SVG 和截图，并确认“图标+文字”与“currentColor 自动适配”两个 UI 决策。
